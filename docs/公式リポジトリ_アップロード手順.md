# QGIS 公式プラグインリポジトリに出す手順（ご自身でやること）

アップロードするファイル：`dist/building_3d_html.zip`（2026-11-13 作成、バージョン 1.0.0）

## 0. 先に確かめること

- **GitHub のリポジトリは、もう「公開（Public）」になっています**（2026-11-13 に確認）。
  公式リポジトリでは、ソースコードを誰でも見られる場所に置くことが条件なので、このままで大丈夫です。
  公開のままだと、`testdata/` の試し用データ（市営住宅の住棟）や README も誰でも見られます。
  見られて困るものがないか、一度だけ GitHub の画面で見ておいてください。
- 今回の変更（英語の README・ライセンス・メタデータなど）はまだコミットしていません。
  公式の画面には GitHub のページへのリンクが出るので、**アップロードの前に GitHub へ送って（push して）おく**のがおすすめです（Claude に「コミットして push して」と頼めば行います）。

## 1. OSGeo ID を作る（初めてのときだけ）

1. ブラウザで https://www.osgeo.org/community/getting-started-osgeo/osgeo_userid/ を開く
2. 「Create an OSGeo ID」から、名前・メールアドレス・パスワードを入れて登録する
3. 届いたメールのリンクを押して、登録を終える

## 2. 公式サイトにログインする

1. https://plugins.qgis.org/ を開く
2. 右上の「Login」を押し、OSGeo ID のユーザー名とパスワードでログインする

## 3. zip をアップロードする

1. ログインしたら、上のメニューの「Plugins」→「**Upload a plugin**」を開く
   （直接開くなら https://plugins.qgis.org/plugins/add/ ）
2. 「Plugin package」で `dist/building_3d_html.zip` を選ぶ
3. 「License」の確認のチェックがあれば、チェックする
4. 「Upload」を押す

名前・説明・作者などは、zip の中の `metadata.txt` から自動で読み込まれます（画面で打ち込む必要はありません）。

## 4. 審査を待つ

- 初めてのプラグインは、ボランティアの審査担当の人が中身を見てから公開されます。**数日〜2週間ほど**かかることがあります。
- 審査の人からの質問や「ここを直して」という連絡は、登録したメールに英語で届きます。
  届いたら、その文を Claude に見せてもらえれば、直し方と返事の文を一緒に考えます。
- 公開されると、QGIS の「プラグインの管理とインストール」で
  「Building Connect & 3D Publish for PLATEAU」と検索して、誰でも入れられるようになります。

## 5. あとで直したとき（新しい版を出すとき）

1. `metadata.txt` の `version=` を上げる（例：1.0.0 → 1.0.1）。同じ番号ではアップロードできません
2. `changelog=` に何を直したかを1行足す
3. zip を作り直して、公式サイトのプラグインのページの「Add version」からアップロードする

## 審査で見られやすい点（確認ずみ）

| 点 | 結果 |
| --- | --- |
| zip の中がトップに `building_3d_html/` フォルダ1つ | OK |
| `__pycache__`・`.pyc`・テストデータ・gpkg などが入っていない | OK（23ファイル、約300KB） |
| ライセンスのファイル（GPL と一緒に使えるもの） | OK（GPL-2.0 以上。`LICENSE` を zip にも入れた） |
| 同梱のライブラリ（MapLibre GL JS） | BSD-3 ライセンスで GPL と一緒に使える。ライセンス文も同梱 |
| ネットへの通信 | プラグイン自体は通信しない。書き出した HTML がブラウザで背景地図（国土地理院タイル）を読む。地図で確かめるボタンは、押したときだけブラウザで Google マップ等を開く。これを `metadata.txt` の説明と英語 README に書いた |
| 個人のパソコンのパス（`C:\Users\...` など）がコードに書かれていない | OK |
| アイコン | OK（`icon.svg`） |
| リポジトリ・不具合報告先（GitHub）が公開されている | OK（Public、Issues も使える） |
| 審査の人が読める英語 | 説明・英語 README・メニューと画面タイトル・各ファイルの冒頭の説明に英語を足した。画面の細かい文字は日本語のまま |
